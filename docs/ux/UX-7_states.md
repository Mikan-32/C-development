# UX-7 状態表示

- 状態：提案
- PRD：4.1、4.3、5.3、7 章（「データ取得や機器操作の失敗を、画面で確認できる」「取得データの不足や分析の失敗を画面で確認できる」）
- 文言の理由コードは AI-2 の 3 章と共通
- モック：v2 の「X-01 状態表示の例」

## 1. 原則

1. **何が起きたか**と**次にどうするか**を必ず一緒に出す。
2. 成功は控えめに、失敗と未確認ははっきり出す。失敗は、ユーザーが見るまで画面に残す（トーストだけで済ませない）。
3. 「保存中」「分析中」「依頼中」など途中の状態を、完了と同じ見た目にしない。
4. 責めない。「〜できませんでした」と事実を書き、「〜してください」より「〜すると直ります」と書く。
5. 赤い全面の警告は使わない。色は `--serious`（オレンジ）まで。

## 2. 状態の一覧

本 PRD の「同期中」は、自前のサーバーがないため **保存中（計測データを DB に書き込んでいる）** と **カーテンの状態の取得中** の 2 つとして扱う。

## 3. カーテンの失敗の理由

| 理由 | 判定 | 文 |
|---|---|---|
| 通信できない | libcurl のエラー（接続・名前解決・タイムアウト） | インターネットにつながりません |
| 認証 | HTTP 401 | 接続の設定を確かめてください（トークン・シークレット・端末の時刻） |
| 機器の応答 | HTTP 200 で `statusCode` が 100 以外 | カーテンが応答しません（ハブがオフラインの可能性があります） |
| 回数の上限 | API の 1 日の上限 | 今日の操作回数の上限に達しました |
| 動いたか不明 | 45 秒以内に確認できない | ST-CURTAIN-UNCONFIRMED |
