# UX-8 表現とアクセシビリティ

- 状態：提案
- PRD：5.1（ダークモードを標準、入力を最小限、責めない・不安をあおらない）、7 章（ダークモードで主要な操作を完了できる）

## 1. デザイントークン（LVGL の色として `ui/nk_theme.h` に定義する）

UI モック v1 の色を引き継ぐ。コントラスト比は WCAG 2.x の計算式で求めた値。

| 名前 | 色 | 用途 |
|---|---|---|
| `bg` | #0E1330 | 画面の背景 |
| `card` | #1A2147 | カード |
| `card-2` | #232B5A | カードの中の区画 |
| `ink` | #F2F3FA | 主な文字 |
| `ink-2` | #B8BCD8 | 補助の文字 |
| `ink-3` | #9298C2 | 注記・目盛り |
| `brand` | #F08CA8 | 主ボタン、選択中のタブ、リンク |
| `brand-ink` | #2A1222 | 主ボタンの上の文字 |
| `series` | #7788EE | グラフ（単一系列） |
| `good` | #5FD3A8 | スコア 70 以上 |
| `warn` | #F2C26B | スコア 55〜69、未確認 |
| `serious` | #F09A6A | スコア 55 未満、失敗（赤は使わない） |
| `night` | #05070F | 計測中・鳴動の画面の背景 |
| `night-ink` | #8A7F9E | 計測中の画面の文字（まぶしさを抑える） |

### コントラスト比（背景に対して）

| 文字 | `bg` | `card` | `card-2` | `night` |
|---|---|---|---|---|
| `ink` | 16.4 | 14.0 | 12.1 | 18.2 |
| `ink-2` | 9.7 | 8.3 | 7.2 | 10.8 |
| `ink-3` | 6.5 | 5.5 | 4.8 | 7.2 |
| `brand` | 7.8 | 6.7 | 5.8 | 8.6 |
| `series` | 5.7 | 4.8 | 4.2 | 6.3 |
| `night-ink` | — | — | — | 5.4 |

- 本文は 4.5 以上（AA）を守る。`series` は `card-2` の上で 4.2 なので、**`card-2` の上にグラフの文字を置かない**（棒そのものは図形なので 3.0 以上で可）。
- 主ボタン：`brand-ink` on `brand` = 7.5。
- UI モック v1 の背景のグラデーションとぼかし（`backdrop-filter`）は、LVGL では負荷が高いので使わない。単色の `bg` と `card` で表現する。

## 2. 文字

| 用途 | 大きさ（論理 px） | 太さ |
|---|---|---|
| スコアの数字 | 40 | Bold |
| 画面の見出し | 24 | Bold |
| カードの見出し | 16 | Bold |
| 本文 | 15 | Regular |
| 注記・目盛り | 12（最小） | Regular |
| 計測中の時計 | 72 | Regular |

- フォント：Noto Sans JP（Regular・Bold）を、使う文字だけのサブセットにして同梱する（tech-stack.md）。サブセットの文字は、UI の文字列表と AI-5 の文型から自動で集める。
- **アプリ内の文字サイズ設定**（標準・大・特大＝1.0／1.2／1.4 倍）を設ける。LVGL で自前に描くため、Android の文字サイズの設定が効かないことへの対策（C4 設計書 7 章のリスク）。LVGL の Tiny TTF で、倍率に合わせた大きさのフォントを作る。
- 数字は等幅の数字を使う（時刻が動いても横に揺れないように）。

## 3. 触れる大きさと配置

- 押せるものは **48×48 以上**（論理 px）。隣との間は 8 以上。
- 主ボタンは画面の下部、親指の届く位置に置く。
- 長押しが必要な操作（計測の停止）は、長押し中に進み具合の輪を表示する。

## 4. 暗い部屋での見やすさ

- 純白（#FFFFFF）の大きな面を使わない。最も明るい色は `ink`。
- 計測中・鳴動の画面は `night` 背景と `night-ink` の文字。
- 動き：スコアのリングが伸びる 1 か所だけ。端末の「アニメーションを削除」の設定は SDL から取れないため、アプリ内の「動きを減らす」設定を設ける。

## 5. 入力を減らす

| 場面 | 工夫 |
|---|---|
| 計測を始める | 前回のサウンド・音量・アラームを覚えておき、1 タップで始める |
| 時刻 | ローラーで選ぶ。キーボードを出さない |
| カーテンの接続 | トークンは貼り付け |
| 朝の気分 | 任意の 1 タップ（3 択）。設定で出さないようにできる |
| UI モック v1 の手入力（就寝・起床・寝つき・習慣・メモ） | 廃止（センサーで記録） |

## 6. 表現のルール

### 言葉の選び方
| 使わない | 使う |
|---|---|
| 要改善、悪い、ダメ | 回復を優先、整えどころ |
| 睡眠不足です | 目標まであと 30 分でした |
| 〜が原因です | 〜の日は〜の傾向がありました |
| 〜してください（命令が続く場合） | 〜してみませんか、〜すると直ります |
| エラーが発生しました | 〜できませんでした。〜すると直ります |
| 異常、危険、病名 | 使わない（相談の案内は AI-5 の FB-12 の文だけ） |

- フィードバックの文型は AI-5 の 6 章の禁止語を単体テストで確かめる。UI の文字列表にも同じチェックをかける（「失敗」は操作結果を正しく伝えるために必要な場合のみ使ってよい）。
- 同じ操作は、同じ言葉で呼ぶ（「おやすみを始める」→ 通知も「おやすみを始めました」）。
- 時刻は「6:30」、長さは「7時間10分」、日付は「10月31日（土）」で統一する。

## 7. アクセシビリティの限界と対策

LVGL は画面を自前で描くため、**TalkBack（画面の読み上げ）と Android の文字サイズの設定は効かない**。PRD の対象範囲にどこまで含めるかはチームで決める（C4 設計書 7 章）。v1 では次の対策をとる。

| 限界 | 対策 |
|---|---|
| 読み上げできない | 重要な結果（スコア、アラーム、カーテンの失敗）は通知にも出す（通知は OS が読み上げる） |
| 文字サイズの設定が効かない | アプリ内の文字サイズ設定（2 章） |
| 色だけで区別しがち | 品質や状態は、色に加えて札の文字（「参考値」「未確認」）や記号で示す |
| グラフが読めない | グラフの数値を一覧でも示す（UX-4 の 3 章） |
