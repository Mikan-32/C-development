# 0007. 睡眠データの仕様と保存期間

- 状態：提案
- 日付：2026-10-31
- 対応タスク：全員タスク 2「データ仕様の決定」
- 詳細：[AI-1 睡眠データの入力仕様](../spec/ai/AI-1_data-spec.md)、[AI-2 データ品質の判定](../spec/ai/AI-2_data-quality.md)

## 背景

PRD 4.1 と 5.2 は、日ごとの睡眠ログの保存、取得できなかった時間の表示、暗号化、削除を求めている。取得項目・頻度・欠損の扱い・保存場所・期間は未定だった。

## 決定

| 項目 | 決定 |
|---|---|
| 取得頻度 | 加速度 50 Hz、マイク 16 kHz、照度は変化時。いずれも端末のメモリ上で処理する |
| 保存する単位 | **30 秒ごとの特徴量（エポック）** と、寝返り・いびき・欠損などの**イベント**、夜ごとの**分析結果** |
| 保存しないもの | 生の加速度、録音（任意で保存する「いびきの録音」を除く。ADR-0010） |
| 欠損の扱い | エポックごとに「取れた割合（0〜1）」を持つ。0.8 未満のエポックは「不明」とし、穴埋めしない。欠損の始まりと終わりと理由をイベントに残す |
| 夜の日付 | 計測を終えた日（起床日）の日付で管理する |
| 時刻 | UTC のミリ秒＋計測開始時のタイムゾーンのずれ（分） |
| 保存場所 | 端末内のアプリ専用領域の SQLCipher DB だけ。サーバーには送らない。端末のバックアップ対象から外す |
| 保存期間 | 夜ごとの分析結果と睡眠段階の並び：ユーザーが消すまで／30 秒ごとの特徴量とイベント：**90 日**で自動削除（分析方法を更新したとき再計算に使うため）／いびきの録音（任意）：**7 日** |
| 削除 | 1 夜ずつ、または全データを削除できる。同意を取り消したときは計測を止め、削除を案内する |
| 版の記録 | 分析結果には分析方法の版を残し、版が変わったら 90 日以内の夜は再計算できるようにする |

## 結果

- 1 夜あたりの保存量は特徴量で 100 KB 程度（30 秒×最大 1,680 エポック）。90 日で 10 MB 程度に収まる。
- 録音を保存しないので、同室の人の声などの個人情報を持たずに済む。
- 生データがないため、あとから別の方法で分析し直すことはできない。アルゴリズムの改善には、同意を得たメンバーの「開発用データ」（`tests/data/`）を使う。
