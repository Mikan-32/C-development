# 0005. 睡眠データはスマホ本体のマイクと加速度センサー（＋照度センサー）から取る

- 状態：提案
- 日付：2026-10-31
- 対応タスク：全員タスク 1「対応範囲の決定」（睡眠データの取得元）
- 関係：C4 設計書 2.2 の仮置きを確定する。仕様の詳細は [AI-1](../spec/ai/AI-1_data-spec.md)

## 背景

- PRD 4.1 は寝返り・呼吸・いびきの取得を求めているが、取得元は未定（8 章）。
- 外部センサー（マット型、ウェアラブル）は、購入費がかかり、多くは独自アプリや OAuth 連携が必要で、C から扱うには Kotlin の量が増える（ウェアラブルの集約先である Health Connect は Kotlin の API しかない）。
- 対象ユーザーは「寝つきが悪い人」「睡眠の質に悩む人」で、追加の機器を買わずに始められることが継続のしやすさ（PRD 2 章）につながる。

## 決定

| 項目 | 取得元 | 取れるもの | 備考 |
|---|---|---|---|
| 寝返り・体動 | 加速度センサー（NDK の ASensorManager、50 Hz） | 体動の量、姿勢の変化 | 主な入力。これがないと分析しない |
| いびき・寝室の音 | マイク（NDK の AAudio、16 kHz・モノラル） | いびきらしい音の秒数、音の大きさ | 端末内で特徴だけを取り出し、録音は保存しない（ADR-0010） |
| 呼吸 | 加速度（細かな揺れ）とマイク（呼吸音） | 呼吸数の推定値 | 取れる夜だけ表示する。取れないことが多い前提で設計する |
| 部屋の明るさ | 照度センサー（任意） | ルクス | カーテン設定のフィードバックに使う。端末にない場合は使わない |

- スマホは**枕元のマットレスの上**（シーツの上、画面を上）に置き、**充電しながら**使うことを推奨する。置き方は初回設定で案内し、10 秒の試し計測で確かめる（UX-1）。
- 同じベッドで寝る人がいる場合は精度が下がることを、置き方の案内に書く。
- 外部センサー・ウェアラブルは v1 の対象外とし、C4 の「外部センサー機器（将来）」のままにする。

## 結果

- 追加の機器なしで使い始められる。必要な Kotlin は夜間サービスだけで済む。
- 加速度だけで「浅い・深い」を分けるのは原理的に限界がある。表示は「推定」とし、REM 睡眠は扱わない（ADR-0008、AI-3）。
- 一晩の常駐による電池と発熱の確認が必須（試作 Issue「SP-2」）。
