# 0006. スマートカーテンは SwitchBot カーテン 3（＋ハブ）とし、クラウド API v1.1 で操作する

- 状態：提案（購入前にチームで費用を確認する）
- 日付：2026-10-31
- 対応タスク：全員タスク 1「対応範囲の決定」（スマートカーテンの機種）

## 背景

- C4 設計書 2.2 では「メーカーがクラウド API を公開している製品」と仮置きしていた。
- Bluetooth で直接操作する方式は、Android では BLE の API が Kotlin にしかないため、ADR-0004 の方針（Kotlin を増やさない）に合わない。
- HTTPS のクラウド API なら、C の libcurl と cJSON（すでに技術スタックにある）だけで操作できる。

## 決定

- 機種：**SwitchBot カーテン 3**。クラウドから操作するために **SwitchBot ハブ**（ハブミニ、ハブ 2、ハブ 3 のいずれか）を併用する。
- API：SwitchBot のクラウド API **v1.1**（`https://api.switch-bot.com/v1.1/`）。
  - 認証：ユーザーが SwitchBot アプリの開発者向け設定で取得したトークンとシークレットを使う。リクエストごとに「トークン＋時刻（ミリ秒）＋ランダムな値」をシークレットで HMAC-SHA256 し、Base64 にした署名をヘッダーに付ける。時刻がずれていると認証に失敗する。
  - 命令：`turnOn`（開ける）、`turnOff`（閉める）、`setPosition`（位置を指定。パラメーターは `0,モード,位置`。位置は 0 が全開、100 が全閉。モード 1 は静音）。
  - 状態：`GET /devices/{id}/status` の `slidePosition`（0〜100）と `moving`（動作中か）。
  - 成否：HTTP 200 でも本文の `statusCode` が 100 以外なら失敗として扱う。
- **命令が受け付けられたことと、カーテンが動いたことを区別する**。命令のあと状態を 3 秒おきに最大 45 秒確認し、`moving` が false になり、位置が目標から 5 以内なら「成功（確認済み）」とする。確認できなければ「未確認」として表示する（PRD 5.3）。
- **予約（開閉時刻）はアプリ側が持つ**。公開 API にはカーテン本体へ予約を登録する機能が見当たらないため、時刻が来たらアプリが命令を送る（platform-boundary.md の 4 章）。
- トークンとシークレットは SQLCipher の DB に保存し、ログに出さない。画面では末尾 4 文字だけ表示する。

## 結果

- Kotlin を増やさずにカーテンを操作できる。PC 版でも、偽のサーバーを立てれば同じコードでテストできる（ADR-0011）。
- 動作にはインターネット接続とハブが必要。ハブやクラウドが止まると操作できないので、その状態を画面に出す（UX-7）。
- 両開き（2 台を連携）の場合に 1 台への命令で両方動くかは、実機で確認する。
- C4 設計書の「開閉時刻の予約（HTTPS）」の表記を直す（platform-boundary.md 7 章）。
- 機器の購入費（カーテン 3 とハブ）が必要。購入できない場合も、偽のサーバーで開発とテストを進められる。
