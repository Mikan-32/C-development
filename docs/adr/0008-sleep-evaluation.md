# 0008. 睡眠状態の推定とスコアの方針

- 状態：提案
- 日付：2026-10-31
- 対応タスク：全員タスク 3「睡眠評価の決定」
- 詳細：[AI-3 推定方法](../spec/ai/AI-3_stage-estimation.md)、[AI-4 スコア](../spec/ai/AI-4_score.md)、[AI-6 不確かな結果の抑制](../spec/ai/AI-6_uncertainty.md)、[AI-7 評価](../spec/ai/AI-7_evaluation.md)

## 背景

- PRD 4.2 は「浅い睡眠・深い睡眠・覚醒を、取得データで推定できる範囲で表示」「不確かな結果を断定しない」を求めている。
- 取得元はスマホの加速度とマイク（ADR-0005）。加速度で睡眠と覚醒を分ける方法（アクチグラフィ）は研究例が多いが、じっと起きている時間を睡眠と見誤りやすい。浅い・深いの区別は脳波なしでは推定の域を出ない。
- 自前のサーバーは持たない（C4 2.2）。

## 決定

- **推定方法**：30 秒ごとの体動から、前後の時間に重みを付けた合計で「覚醒／睡眠」を決め、短い区間を整える。睡眠のうち、10 分以上ほぼ動きがない区間を「深い眠り（推定）」、それ以外を「浅い眠り」とする。取れなかった時間は「不明」として残す。**REM 睡眠は扱わない**。
- **方式**：端末内の規則ベース（学習済みモデルは使わない）。しきい値は設定値として持ち、実データでの調整（AI-7）で更新する。
- **スコア**：100 点満点。睡眠時間 30、寝つき 15、連続性 25、効率 15、規則性 15。深い眠りの割合は推定の確からしさが低いため**スコアに入れない**。取れない項目は除いて満点を割り戻し、残りが 70 点分未満なら点数を出さない。
- **ラベル**：85 以上「とても良い」、70〜84「良い」、55〜69「まずまず」、55 未満「回復を優先」。赤色や「悪い」「要改善」は使わない（PRD 5.1）。UI モック v1 の「要改善」は置き換える。
- **確からしさ**：夜ごとに「高・中・低」を付ける。「低」のときはスコアに「参考値」を添え、傾向の計算から外す。
- **検証**：今は合成データで処理の正しさを確かめる（AI-7 の第 1 段）。実機が揃ったら、同意したメンバーの夜の記録と睡眠日誌（寝た時刻・起きた時刻・寝つき）を比べる（第 2 段）。

## 結果

- 説明できる単純な方法なので、C での実装と単体テストがしやすい。Python の参照実装と期待値データ（`tests/golden/analysis/`）を、C の実装の答え合わせに使える。
- 推定の限界（じっと起きている時間、同じベッドの人の動き）は、ユーザー向けの説明文（AI-3 の 6 章）で正直に伝える。
- UI モック v1 のスコア式（気分の入力を含む）は使わない。気分は任意の 1 タップ入力として残し、スコアには入れない。
