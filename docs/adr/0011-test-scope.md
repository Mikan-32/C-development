# 0011. 実機がない場合の代わりのテストと、実機で確認する範囲

- 状態：提案
- 日付：2026-10-31
- 対応タスク：全員タスク 6「テスト範囲の決定」
- 手順書：[tests/manual/](../../tests/manual/README.md)

## 背景

- アラーム、一晩の計測、カーテンは、実機や機器がないと確認できない。一方で、メンバー全員が Android の実機とカーテンを持っているとは限らない。
- PRD 7 章の受け入れ条件は、すべて確認できる必要がある（CS-10）。

## 決定

### テストの段
| 段 | どこで | 何を | 自動 |
|---|---|---|---|
| 1. 単体テスト | PC（CI：Linux＋Windows） | 分析・スコア・フィードバック・品質判定・セッションの状態・自動モードの判断・カーテン API の組み立てと応答の解釈・DB | ○ |
| 2. 期待値テスト | PC（CI） | `tests/golden/analysis/` の入力に対し、C の分析結果が Python 参照実装と一致するか（許容差あり） | ○ |
| 3. 再生テスト | PC（CI） | `tests/data/` の録音・センサーログを計測処理に流し、いびき・体動の検出数が記録と一致するか | ○ |
| 4. 画面の確認 | PC 版アプリ | 全画面と全状態（UX-7）を、PC 版の代役と「状態を切り替えるデバッグ設定」で表示し、スクリーンショットを撮る | 手動 |
| 5. 偽サーバーでの結合 | PC | カーテン API の偽サーバー（成功・失敗・遅延・認証エラー・`moving` が終わらない）に対して、結果の 3 状態が正しく出るか | ○ |
| 6. エミュレーター | Android エミュレーター | 権限の流れ、アラームの登録と再起動後の再登録、Doze 中のアラーム、通知、全画面通知、サービスの起動制限 | 手動（adb の手順書） |
| 7. 実機 | Android 実機 | 一晩の計測（電池・発熱）、実際のセンサーの値、画面ロック中・アプリ終了中のアラーム、画面オフでのサウンド、日本語フォントとタッチ、16KB ページサイズ | 手動 |
| 8. 機器 | 実機＋カーテン 3＋ハブ | 開閉、位置指定、状態確認、ハブを切ったときの表示 | 手動 |

### 実機で必ず確認する範囲（エミュレーターでは代われない）
1. 一晩（6 時間以上）の計測で、電池の減りが 20% 以下、端末が熱くならない
2. 画面ロック中・アプリをスワイプで終了した後・再起動後にアラームが鳴る
3. 画面を消しても入眠サウンドが止まらない
4. 実際のマイクと加速度で、寝返りといびきが記録される
5. 日本語が欠けずに表示され、指で操作できる

### 機器がない間の進め方
- カーテンは偽サーバーで開発し、購入後に段 8 の手順書を実施する。
- 実機を持たないメンバーは、段 1〜5 を担当する。実機の確認は、実機を持つメンバーが手順書に沿って行い、結果を Issue に残す。

### 受け入れテストとの対応
PRD 7 章の各条件を、どの段で確かめるかを [tests/manual/acceptance-matrix.md](../../tests/manual/acceptance-matrix.md) にまとめる。CS-10 はこの表に沿って実施する。

## 結果

- 実機・機器がなくても、ロジックの大半を毎回自動で確認できる。
- PC 版にも「状態を切り替えるデバッグ設定」と「時刻の早送り」が必要になる（`platform/pc/` の代役に追加）。
- 段 6〜8 は手順書の質に左右されるので、手順書もレビューの対象にする。
