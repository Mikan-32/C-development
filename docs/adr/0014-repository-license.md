# 0014. リポジトリのライセンスを MIT にする

- 状態：提案（先生への確認が済むまで承認しない）
- 日付：2026-10-31
- 関係：README.md の「ライセンス：未定」、third_party/README.md の「ライセンス表示」

## 背景

- リポジトリは公開されている。ライセンスがないと、他人は読むことはできても、使ったり改変したりする権利がない。
- 使っている外部ライブラリは、どれも条件のゆるいライセンス（zlib、MIT、BSD 系、curl、Apache-2.0、SIL OFL）で、どのライセンスを選んでも組み合わせの問題は起きにくい。
- 各メンバーが書いたものの著作権は、それぞれのメンバーにある。ライセンスを付けるには全員の同意が要る。
- 授業の成果物なので、学校に権利やライセンスの決まりがある可能性がある。

## 検討した案

| 案 | 内容 | 良い点 | 気になる点 |
|---|---|---|---|
| **A（推奨）MIT** | 著作権表示と許諾文を残せば、誰でも使える | 短く分かりやすい。外部ライブラリと相性がよい | 他人が改変版を公開しても、変更点を公開する義務はない |
| B Apache-2.0 | MIT に、特許の扱いを加えたもの | 特許の条項がある | 文書が長く、NOTICE ファイルの扱いなど手間が増える |
| C 付けない | すべての権利を手元に残す | 他人に使わせたくない場合に向く | GitHub の規約により、閲覧とフォークはできる。学習のために公開する意味が薄れる |
| D GPL | 改変版も同じライセンスで公開する義務がある | 改変版の公開を求められる | アプリを配るときの制約が大きい |

## 決定

- 案 A（MIT）とする。
- 対象：`third_party/` と `assets/`（フォントや音源など、それぞれのライセンスがあるもの）を除く、このリポジトリのすべて（コード、docs、画像）。
- 著作権者の表記：`Copyright (c) 2026 ねむのき開発チーム（C-development contributors）`
- 承認の前に、担当の先生に、授業の成果物の権利やライセンスに決まりがないかを確認する。メンバー全員の同意を Issue か PR に残す。

## 結果

- ルートに `LICENSE` を置き、README.md の「ライセンス」を更新する。
- `assets/` の素材は、それぞれのライセンスに従い、出典とあわせて記録する（ADR-0010 の `assets/sounds/LICENSES.md` など）。
- アプリの ST-04（ライセンス表示）に、外部ライブラリと素材のライセンスを載せる。
- この ADR は法律の助言ではない。判断に迷う場合は、先生や学校の窓口に確認する。
